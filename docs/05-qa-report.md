## 3. Accuracy (D3), measured
Run: synthetic dataset seed 2026, 40 mark sheets + 30 photos. Results are identical from the command line, the admin page and the image build.

| Measure | Result | Target |
|---|---|---|
| False matches on planted errors | **0** | 0 (gate) |
| Mark extraction, clean sheets | 100 % (112 / 112) | ≥ 95 % |
| Mark extraction, degraded sheets | 100 % (113 / 113) | reported |
| Wrong values trusted by OCR | 0 | 0 |
| Planted-error recall / precision | 100 % / 100 % | 100 % / reported |
| Correct applications sent to review (false alarms) | 0 % | reported |
| Photo rule agreement (30 photos × 8 rules) | 100 % (240 / 240) | 100 % |

### Robustness probe: held-out seed 7, never used during development
| Degradation | Degraded accuracy | Unsure → review | Wrong but trusted | False matches | Correct apps → review |
|---|---|---|---|---|---|
| Standard (as in D3) | 100 % | 0 | 0 | 0 | 0 % |
| Harsh (skew 3.5°, blur 1.3–1.8, 50–62 % light) | 98.2 % | 2 | 0 | 0 | 8.3 % |
| Extreme (skew 5°, blur 1.8–2.6, 38–50 % light) | 2.7 % | 109 | 0 | 0 | 50 % |

**Interpretation:** as images get worse, the engine reads fewer marks with confidence. But it **never trusts a wrong value**. Unreadable marks go to manual review, as NFR-03 requires. The cost of very bad scans is reviewer time, not wrong decisions.

**Honest limit:** all of this data is synthetic, generated by our own tool with the same fonts and layouts. These figures show that the method works on these templates. They do **not** measure accuracy on real mark sheets.

## 6. Bugs found and fixed during QA
| # | Bug | Found by | Fix |
|---|---|---|---|
| B1 | Upscaling small photos made them look blurry | Dataset label check | Never upscale for sharpness |
| B2 | Dark photos were judged blurry | Dataset label check | Contrast-normalised sharpness; default retuned to 25 🔧 |
| B3 | Marks not found under multi-word column titles | First OCR run | Anchor on the whole column title |
| B4 | Subject names lower-cased in the completeness message | US-06 test | Capitalise the first letter only |
| B5 | CBSE grade "C1" misread as "Cl" broke subject matching | CBSE dataset run | Subject name = words before the first number |
| B6 | Tesseract threads oversubscribed the CPU | Load monitoring | `OMP_THREAD_LIMIT=1` in the image |
| B7 | **Out-of-memory crash loop on 512 MB hosts** | Container test with Render limits | Memory-light noise generation; startup run attempted once; demo data prebuilt into the image |
| B8 | Possible decompression-bomb upload | Security review | Pixel cap at upload and in the engine |

## 7. Known limitations (not defects)
- Only synthetic TN HSC and CBSE XII layouts are supported. Other layouts go to manual review.
- No PDF upload yet (Should O-9). Photo checks can't confirm identity.
- On Render's free plan, validation takes about 20 s per application, and the first visit after idle takes about a minute while the service wakes.
- Browsers other than Chromium have not been tested.
